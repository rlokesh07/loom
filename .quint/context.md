# Bounded Context

## Vocabulary
Tool: A reusable component that performs a specific operation (e.g., WebSearchTool, CalculatorTool) with parameters and returns a ToolResult. Agent: An autonomous entity that uses CompletionEngines (LLMs) to reason and execute Tools to accomplish tasks. CompletionEngine: An abstraction over LLM APIs (ChatGPT, Gemini, Ollama) that provides text generation and function-calling capabilities. ToolRegistry: A registry that manages available tools and provides them to agents for execution. Parameter: A typed input definition for a Tool with validation and schema generation capabilities. ToolResult: An encapsulation of tool execution outcomes (success/failure) with type-safe data extraction. API Server: A stateless HTTP server that exposes agent capabilities via REST endpoints with Supabase authentication. LLM: Large Language Model - the underlying AI that powers agent reasoning and decision-making.

## Invariants
Must use C++20 standard with CMake build system. All tools must inherit from the base Tool class and implement execute() method. Must support JSON schema generation for LLM function calling integration. Must maintain type safety using std::any and ToolResult encapsulation. External API calls require environment variables for API keys (BRAVE_SEARCH_API_KEY, GITHUB_TOKEN, OPENAI_API_KEY). Must use nlohmann/json library for JSON operations. HTTP requests use libcurl. No circular dependencies between components. Agent execution must handle errors gracefully and return ToolResult status. State management is optional per tool via set_state/get_state methods. API server must authenticate requests via Supabase integration.
